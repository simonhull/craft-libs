# craft-mobile UI primitives (v1)

Generated by `UPDATE_CATALOGUE=1 cargo test -p craft-mobile`. Do not edit.

An app describes each native panel as a list of these nodes (`craft_mobile::ui`), and the shell draws them with the platform's own controls. A node says what a control is, never where it goes. Every node has an `id`, unique in its panel.

When the user changes a control, the shell sends an edit: the panel, the control's `id`, a phase (`begin`, `change`, `commit` or `cancel`), a gesture number shared by every edit of one drag, and the value. The app applies it and describes the panel again; if it rejects the edit, the shell gets the panel again unchanged and the control goes back to the app's value.

A shell sends edits only for the user's own gestures, never while showing a value the app sent: a rejected edit is answered with the old value, and an edit for that would loop.

## `number`

A value in a range: a slider, with the value shown beside it; tap the value to type one.

**Fields:** `value` within `min`..=`max`; `step` snaps it (`null`: continuous); `scale: "log"` spreads the slider by ratio, for a wide range such as a brush size (needs `min` above 0; left out, the slider is linear); `unit` is `none`, `percent` (a 0..=1 value shown as 0–100 %), `pixels` or `degrees`; `enabled: false` greys it out. Values and edits are in the number's own units whatever the scale.

```json
{
  "type": "number",
  "id": "size",
  "label": "Size",
  "value": 24.0,
  "min": 1.0,
  "max": 5000.0,
  "step": 1.0,
  "scale": "log",
  "unit": "pixels",
  "enabled": true
}
```

**Sends:** `number` edits: `begin`, `change` while dragging, then `commit` (or `cancel`); a typed value is one `commit`.

For example:

```json
{"action":"edit","panel":"brush","control":"size","phase":"change","gesture":7,"value":{"kind":"number","value":120.0}}
```

## `toggle`

On or off: a switch.

**Fields:** `value`; `enabled: false` greys it out.

```json
{
  "type": "toggle",
  "id": "visible",
  "label": "Visible",
  "value": true,
  "enabled": true
}
```

**Sends:** one `toggle` edit, `commit`.

For example:

```json
{"action":"edit","panel":"layers","control":"visible","phase":"commit","gesture":8,"value":{"kind":"toggle","value":false}}
```

## `choice`

One of several options: segmented for up to 4, a menu for more.

**Fields:** `value` is the chosen option's `id`; option ids are unique; `enabled: false` greys it out.

```json
{
  "type": "choice",
  "id": "blend",
  "label": "Blend Mode",
  "value": "normal",
  "options": [
    {
      "id": "normal",
      "label": "Normal"
    },
    {
      "id": "multiply",
      "label": "Multiply"
    },
    {
      "id": "screen",
      "label": "Screen"
    }
  ],
  "enabled": true
}
```

**Sends:** one `choice` edit with the option's `id`, `commit`.

For example:

```json
{"action":"edit","panel":"layers","control":"blend","phase":"commit","gesture":9,"value":{"kind":"choice","value":"multiply"}}
```

## `section`

A titled group of other nodes; the user can collapse it.

**Fields:** `children` are any nodes; `collapsed` is how it starts.

```json
{
  "type": "section",
  "id": "layer",
  "title": "Layer",
  "collapsed": false,
  "children": [
    {
      "type": "toggle",
      "id": "locked",
      "label": "Lock",
      "value": false,
      "enabled": true
    }
  ]
}
```

**Sends:** nothing itself; its children send their own edits.

## `item_list`

Rows of items such as layers, top to bottom: tap to select, swipe to hide, long-press for Rename and the row's own actions, drag to reorder. Select in the header picks several rows, tap by tap, until Done; with a keyboard, Shift-tap selects a range and Command-tap adds or removes a row.

**Fields:** each row's `id` is the app's own and unique in the list; `depth` indents it (inside groups); `visible: null` means it can't be hidden; `reorderable` allows dragging. A row's `actions` (left out: none) are what the user can do to it, in its context menu after Rename: each has an `id` unique in the row, a `label`, an `icon` (an SF Symbol name, or `null`) and `destructive` (tinted red, and a trailing swipe action too); `icon` and `destructive` may be left out. `rename: "no"` takes Rename… away from a row with no name of its own to change (an open document); left out, a row can be renamed.

```json
{
  "type": "item_list",
  "id": "layers",
  "rows": [
    {
      "id": 2,
      "title": "Sky",
      "subtitle": "Pixel",
      "depth": 0,
      "visible": true,
      "selected": true,
      "actions": [
        {
          "id": "duplicate",
          "label": "Duplicate",
          "icon": "plus.square.on.square",
          "destructive": false
        },
        {
          "id": "delete",
          "label": "Delete",
          "icon": "trash",
          "destructive": true
        }
      ]
    },
    {
      "id": 1,
      "title": "Background",
      "subtitle": "Pixel",
      "depth": 0,
      "visible": true,
      "selected": false,
      "actions": [
        {
          "id": "duplicate",
          "label": "Duplicate",
          "icon": "plus.square.on.square",
          "destructive": false
        },
        {
          "id": "delete",
          "label": "Delete",
          "icon": "trash",
          "destructive": true
        }
      ]
    }
  ],
  "reorderable": true
}
```

**Sends:** `select`, `set_visible`, `rename`, `action` and (when reorderable) `move` edits, each one `commit`, naming rows by their `id`. A `select` has a `mode`: `replace` (a plain tap; also when left out), `toggle` (add the row or take it out) or `range` (from the last row selected to this one). An `action` names the row and the action's `id`: `{"kind":"action","value":{"row":2,"action":"delete"}}`. A `move` names the row dragged; an app moves the whole selection when that row is one of several selected.

For example:

```json
{"action":"edit","panel":"layers","control":"layers","phase":"commit","gesture":10,"value":{"kind":"move","value":{"row":1,"target":2,"position":"above"}}}
```

## `tool_palette`

The app's tools, in a panel with the `rail` role: a vertical Liquid Glass rail at the canvas's leading edge. Tap a tool to select it; long-press a slot (a small corner mark says it has more) for its flyout of the other tools; double-tap the selected tool, or the rail's options button, for its options.

**Fields:** `slots`, top to bottom, each with `tools`: the slot shows the selected tool when it holds it, else its first. A tool has an `id` (unique in the palette), a `label`, an `icon` (`symbol`, an SF Symbol name; `letter`, shown when the platform has no such symbol; the label's first letter when neither works) and a `shortcut` or `null`. `selected` is one of the tools. `options` names the app's Tool panel for the selected tool's options; without one, `fallback_options` is a command that shows them the app's own way; both `null`: no options.

```json
{
  "type": "tool_palette",
  "id": "palette",
  "slots": [
    {
      "tools": [
        {
          "id": "move",
          "label": "Move",
          "icon": {
            "symbol": "arrow.up.and.down.and.arrow.left.and.right",
            "letter": "V"
          },
          "shortcut": "V"
        }
      ]
    },
    {
      "tools": [
        {
          "id": "brush",
          "label": "Brush",
          "icon": {
            "symbol": "paintbrush.pointed",
            "letter": "B"
          },
          "shortcut": "B"
        },
        {
          "id": "pencil",
          "label": "Pencil",
          "icon": {
            "symbol": "pencil",
            "letter": "N"
          },
          "shortcut": "N"
        }
      ]
    },
    {
      "tools": [
        {
          "id": "smudge",
          "label": "Smudge",
          "icon": {
            "symbol": null,
            "letter": "S"
          },
          "shortcut": null
        }
      ]
    }
  ],
  "selected": "brush",
  "options": "brush",
  "fallback_options": "window.toggle.optionsBar"
}
```

**Sends:** one `choice` edit with the tool's `id`, `commit`, when a tool is tapped or picked from a flyout. Options open the `options` panel as a popover from the rail, or send `{"action":"command","id":…}` with `fallback_options`.

For example:

```json
{"action":"edit","panel":"tools","control":"palette","phase":"commit","gesture":11,"value":{"kind":"choice","value":"pencil"}}
```

## Wire

The app sends the shell its panels (request kind 13) whenever they change: `panels`, every panel it offers, and `open`, the open ones described, by id. Each entry of `panels` has an `id`, a `title`, an `icon` (an SF Symbol name; Android maps it to a Material icon) and a `role`: `inspector` slides in beside the canvas, `tool` is a popover from its toolbar button, `rail` is a vertical rail at the canvas's leading edge, always on screen (its `tool_palette`).

```json
{
  "panels": [
    {
      "id": "layers",
      "title": "Layers",
      "icon": "square.3.layers.3d",
      "role": "inspector"
    },
    {
      "id": "brush",
      "title": "Brush",
      "icon": "paintbrush.pointed",
      "role": "tool"
    }
  ],
  "open": {
    "layers": {
      "id": "layers",
      "title": "Layers",
      "role": "inspector",
      "nodes": [
        {
          "type": "toggle",
          "id": "visible",
          "label": "Visible",
          "value": true,
          "enabled": true
        }
      ]
    }
  }
}
```

The app can also ask the shell to open one of its panels (request kind 14, the panel's `id` as text; `Platform::open_panel`), for its own way in to a panel the shell now shows natively, such as a menu item. The shell opens it in its role's place, as its toolbar button would, and then says which panels are on screen (`open_panels`, below) as usual; an id the app doesn't offer opens nothing. Unlike the panels, it isn't sent again to a shell that starts listening later.

The shell sends messages through the same call as its actions (`craft_action`, `CraftNative.action`). It says which panels are on screen, and gets them all again:

```json
{"action":"open_panels","open":["layers"]}
```

And it sends edits, one message each; here the user switched Visible off:

```json
{
  "action": "edit",
  "panel": "layers",
  "control": "visible",
  "phase": "commit",
  "gesture": 3,
  "value": {
    "kind": "toggle",
    "value": false
  }
}
```

## Chrome

A shell that draws parts of the app's chrome natively says so each time it starts the app, before it says which panels are on screen (`CraftApp::shell`); the app then hides its own versions. The features are `panels`, `menus`, `rail` and `status`; a name the app doesn't know is ignored:

```json
{"action":"shell","features":["panels","menus","rail","status"]}
```

A `command` without `params` runs the app's command as its menu item does (`CraftApp::command`); with `params` it is the app's `Action::Command`, as before. A `shortcut` goes to the app's own key handling (`CraftApp::shortcut`).

### `menu_bar` (request kind 15)

The app's menus, in the iPad menu bar (pointer at the top edge, or hold ⌘) and a toolbar menu for touch. `Platform::set_menu` sends it whenever it changes (request kind 15), and again when the shell restarts.

**Fields:** `menus`, left to right, each a `title`, a `role` and `items`. The `role` (`file`, `edit`, `view`, `window` or `help`; `null` or left out for a menu of the app's own) says which system menu it takes the place of, matched by role and never by its translated title; Window keeps the system's window items after the app's. An item is a `command` (an `id` unique in the whole bar, a `label`, a `shortcut` in the portable form such as `Cmd+Shift+Z` or `null`, `enabled`, and `checked`: `true` or `false` for a check mark, `null` for none), a `separator`, or a `submenu` with a `label` and `items`. Labels are never empty. A shortcut's modifiers are `Ctrl`, `Cmd`, `Alt` and `Shift` (`Ctrl` is the Control key, not ⌘), then one key: a character or a named key (`Enter`, `Tab`, `ArrowUp`, `F5`).

```json
{
  "menus": [
    {
      "title": "Edit",
      "role": "edit",
      "items": [
        {
          "type": "command",
          "id": "edit.undo",
          "label": "Undo",
          "shortcut": "Cmd+Z",
          "enabled": true,
          "checked": null
        },
        {
          "type": "command",
          "id": "edit.redo",
          "label": "Redo",
          "shortcut": "Cmd+Shift+Z",
          "enabled": false,
          "checked": null
        },
        {
          "type": "separator"
        },
        {
          "type": "submenu",
          "label": "Transform",
          "items": [
            {
              "type": "command",
              "id": "image.flip_horizontal",
              "label": "Flip Horizontal",
              "shortcut": null,
              "enabled": true,
              "checked": null
            }
          ]
        }
      ]
    },
    {
      "title": "View",
      "role": "view",
      "items": [
        {
          "type": "command",
          "id": "view.rulers",
          "label": "Rulers",
          "shortcut": "Cmd+R",
          "enabled": true,
          "checked": true
        }
      ]
    },
    {
      "title": "Layer",
      "role": null,
      "items": [
        {
          "type": "command",
          "id": "layer.new",
          "label": "New Layer",
          "shortcut": "Cmd+Shift+N",
          "enabled": true,
          "checked": null
        }
      ]
    }
  ]
}
```

**Sends:** a `command` with the item's `id` when the user picks an item without a shortcut; a `shortcut` with its `keys` when the item has one, or the keys are pressed on a hardware keyboard, so the app's own key handling decides, as for the key itself. Enabled and checked are read when a menu opens, so changing them alone redraws nothing.

For example:

```json
{"action":"command","id":"image.flip_horizontal"}
{"action":"shortcut","keys":"Cmd+Z"}
```

### `status` (request kind 16)

What the app is telling the user: a message as a transient toast at the top (red for an error), and a long job as a progress capsule with a Cancel button. `Platform::set_status` sends it whenever it changes (request kind 16), and again when the shell restarts.

**Fields:** `message` (`null` for none): its `text`, its `tone` (`info` or `error`) and an `id` (0 when left out). Give each new message a new id (`Status::message_id`) so the same text said again shows again, and keep the id while the message stands: new text with the same id (a countdown) updates the toast on screen in place, without showing it again, and a toast the user dismissed stays dismissed. Without an id (0), a message shows when its text or tone changes. `progress` (`null` for none): a `label`, a `fraction` from 0 to 1 (`null` while unknown) and `cancel`, a command id or `null` for a job that can't be stopped.

```json
{
  "message": {
    "text": "Couldn't open b.psd: not a Photoshop file",
    "tone": "error",
    "id": 7
  },
  "progress": {
    "label": "Exporting a.png",
    "fraction": 0.4,
    "cancel": "job.cancel"
  }
}
```

**Sends:** the `cancel` command when the user taps Cancel.

For example:

```json
{"action":"command","id":"job.cancel"}
```
